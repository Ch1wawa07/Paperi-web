## 1. 产品定位与 V1 范围（已定稿）

**品牌：Paperi 纸里。** 定位：面向广告、新闻传播、社会学等人文社科研究初学者的 AI 研究导航网页。

**唯一主线：** 用户用日常语言表达一个模糊的社会观察 → 与 AI 探索不同研究视角 → 确认研究种子 → 搜索、核验、收藏真实文献 → 利用文献关系星图拓展 → 形成定量或质化初步研究设计 → 生成可编辑、可保存、可导出的初步研究方案。

**V1 终点 = B：研究设计导航型。** 不做完整论文代写、全套 SPSS、问卷发布/回收、复杂统计分析、全自动文献综述、原生手机 App。V1 的成果不是“完整开题报告”，而是“初步研究设计方案”；候选理论、变量和待证实的研究空白须清晰标记其未验证状态。

### 六个主要页面和路由

1. `/` 首页 Home：品牌欢迎区、开始探索、继续已有项目、热点入口；无真实数据时使用友好空状态。
2. `/lab` 灵感实验室 Idea Lab：左侧连续 AI 聊天，右侧候选研究方向/概念卡片；允许编辑、采纳、保存“研究种子”；热点卡入口。聊天不能自行覆盖用户已确认的研究问题。
3. `/literature` 文献探索 Literature：从研究种子生成可编辑的中英文检索词；用真实学术接口检索论文，查看题名、作者、年份、期刊/来源、摘要、DOI 或可核验链接，保存到项目文献库；明确标识只有摘要还是可访问全文，AI 不得虚构全文细节。
4. `/map` 文献星图 Literature Map：围绕一篇真实论文展示一层真实的参考文献与后续引用，节点可查看详情、收藏和切换焦点；真实引用与仅主题相关的边必须视觉区分；无关系时显示空状态。有限节点数量与缩放/拖动，避免性能问题。
5. `/canvas` 研究设计画布 Research Canvas：可选择“定量路径”与“质化路径”。前者包括研究问题、构念/变量、候选假设、抽样/测量建议；后者包括问题、对象/情境、探索主题、访谈/观察/文本分析建议。支持内容编辑、保存、关联用户所选文献和来源。不能把质化项目强制画成自变量—因变量图。
6. `/proposal` 研究方案 Proposal：汇总已确认研究问题、研究背景、真实文献、候选理论、变量或主题、方法、可行性与待验证问题；支持编辑、保存、Markdown 导出（优先），PDF（后续若稳定可加）。编辑需保留用户修改，AI 更新不得无提示覆盖。

### 全局能力

- 同一项目持有聊天、确认的研究种子、收藏文献、用户笔记、研究设计、方案稿及其更新时间；在页面间复用、刷新后可恢复。
- 让用户从任意页面查看当前项目、返回上一环节；不强迫线性流程。
- 结果具有明确状态：`AI 建议 / 用户已确认 / 有文献依据 / 待核实`，不要混淆。
- 所有网页的按钮、搜索、收藏、跳转、编辑、保存、导出都必须有真实事件与反馈，无假按钮。
- PC 桌面网页优先；手机至少可正常浏览主要内容，不发生严重布局溢出。

## 2. 关键交互说明

### 2.1 首页

- 首访：看到“今天，你对什么感到好奇？”以及可输入自然语言的入口。
- 已有项目：项目卡显示用户真实项目名、上次更新时间和导航阶段；可以继续、创建新项目。
- 如果尚未连接 AI，首页仍然可以显示，但提交 AI 探索时必须解释服务暂不可用。

### 2.2 灵感实验室

- 用户输入：“我发现现在很多人买东西都开始问 AI，而不是去搜索平台，我不知道这算不算研究题目。”
- AI 给出 2–3 种不同候选视角，例如消费者信任、商业推荐透明度、平台与权力；使用通俗解释，少量追问，不进行一连串盘问。
- 右栏出现候选卡：标题、通俗描述、候选概念、为什么值得探索、待确认问题。用户可以编辑、采纳、丢弃。
- 只有用户点击采纳，才进入已确认的研究种子；继续聊天不会静默覆盖。
- 对话历史在本项目内保存，跨页面返回仍在。
- 热点卡显示可靠的新闻/学术来源和明确日期；没有可靠自动热点接口时使用人工精选、标注发布日期和示例性质，不冒称“今日实时热点”。

### 2.3 文献探索

- 以 OpenAlex 为优先真实数据源；可考虑 Crossref 校验 DOI；请求在服务端代理中处理，限制请求、缓存和错误反馈。
- 2026 年的 OpenAlex API 可在轻量使用场景无密钥尝试，规模使用建议免费 API key；应支持 key 环境变量且正确处理限额、429、超时、空结果。
- 统一文献数据结构；使用 OpenAlex work id 或 DOI 去重，不能把某种主题关系当成引用关系。
- DOI、作者、年份、摘要等缺失时明确缺失，禁止补造。

### 2.4 文献星图

- 引用/被引用仅来自可核验关系数据；不同关系使用不同颜色或线型及图例。
- 点击节点可打开论文详情，可将论文加到当前项目。
- 初始支持一层关系、节点数量上限、性能保护和真实数据加载/空状态。
- 可使用 React Flow 或其他成熟可视化库，允许泛型结构以扩展至研究设计画布。

### 2.5 研究设计与成果

- AI 生成候选理论与方法须依据用户确认问题和已收藏文献，同时标出证据不足的建议；不能自动冒称量表“已验证”。
- 用户可以手动新增、修改、删除研究设计要素，不一定只能用 AI 生成。
- 导出使用实际内容，不以空白占位文档冒充成果。

## 3. 数据与安全设计

推荐概念实体：

- `Project`：id、ownerId（如适用）、name、discipline、status、createdAt、updatedAt。
- `ExplorationSession` 和 `ChatMessage`：projectId、role、content、createdAt。
- `ResearchSeed`：projectId、rawObservation、researchAngle、workingQuestion、concepts、confirmationStatus、version。
- `Paper`：openAlexId、doi、title、authors、year、venue、abstract、primaryUrl、metadataSource；对单篇作品只保留一个规范标识。
- `ProjectPaper`：projectId、paperId、notes、tags、savedAt。
- `CitationEdge`：fromPaperId、toPaperId、relationshipType、source。只保存真实可核验引用关系。
- `ResearchDesign`：projectId、methodTrack、workingQuestion、theoriesOrThemes、variablesOrTopics、hypothesesOrPrompts、methods、evidenceLinks、confirmedFields、updatedAt。
- `Proposal`：projectId、sections、userEdits、lastGeneratedAt、updatedAt。

推荐 Supabase PostgreSQL 与 RLS，若允许不注册体验则用 Supabase 匿名身份（不是开放公共写入）；明确告知匿名用户更换设备/清除浏览器数据可能无法找回匿名项目。**本轮如果没有 Supabase 配置，允许先用类型安全的本地存储适配器做可验证的阶段 1 持久化，并隔离数据访问层，以便阶段 2 切换真实数据库。** 不得将 localStorage 宣称为已经实现云同步。阶段 1 不要强行假设数据库已创建。

## 4. 技术建议（可根据仓库现状合理微调）

- Next.js（App Router）+ React + TypeScript。
- Tailwind CSS + 精细定制 CSS；必要时可采用轻量 UI 原语与无障碍组件。
- React Flow (`@xyflow/react`) 供星图和研究设计画布扩展。
- Supabase 用于后续项目持久化；RLS 限制各自项目访问。绝不暴露 Supabase service role key。
- AI 大模型通过服务端 API 接入，可配置提供商/模型；密钥从服务器环境变量加载，提供限额、错误状态和输入约束，避免 API 费用无限增长。
- OpenAlex 提供真实书目与文献引用关系。注意中文社会科学覆盖不等同于知网，允许后续手动导入文献。
- 尽量避免在 V1 引入独立 Python 服务、微服务和过度复杂 Agent 框架。

## 5. 视觉与 UX 规范：Soft Glass × Editorial Workspace

参考用户提供的“柔性美学 / Soft Aesthetics”图片的**材质和氛围**，不是逐像素复制第三方设计。最终视觉应像独立高品质的年轻研究工具，而非通用 admin dashboard。

- 基调：奶白、云雾、深海蓝、冰川青、鸢尾紫、低饱和蜜桃粉；例如 `#F4F6F8`、`#183247`、`#82D0DC`、`#C9ADEA`、`#F2AFAE`。
- 特色：半透明磨砂玻璃、带纵深的模糊光晕、柔软流动的浅色渐变、微妙悬浮反馈、圆润而克制的形态、精致排版。
- 首页与灵感实验室更有品牌感；阅读正文、文献详情和长内容需要实色或高对比背景，不要牺牲可读性。
- 桌面首页可以使用大幅渐变欢迎区 + 真实项目卡 + 热点/探索入口；项目内使用清晰导航 + 工作区 + AI 建议侧栏的结构。
- 文献星图可采用低饱和深海色背景，节点用柔和发光，不要花哨到难以辨认连接。
- 加载、错误、无结果、未配置状态都要设计；动画简洁，尊重 reduced-motion 设置。
- 完整响应式布局：桌面 1280/1440px、平板约 768px、手机约 390px 验证，不出现不可用的悬浮层与重叠文本。
- 禁止大量无功能数字卡、胡乱填充的假论文和占位趋势统计；品牌可以俏皮，学术信息必须严谨。

### 阶段 1（**本轮立即实现，到此停止**）：搭建可运行的高质量基础工程

1. 检查仓库及分支，简述已有文件、冲突和技术状态；保持当前仓库为唯一工程。

4. 实现 Paperi 全局设计 Token、通用组件、响应式导航、六个可访问的页面路由，以及有品牌辨识度的首页。每个未实现的业务页面明确写“功能将在后续阶段接入”，不得放假聊天结果或假文献。

6. 建立统一的空状态、加载状态、错误提示、用户反馈组件；为全局设置合理的可访问性和语义标签。

### 阶段 3（后续单独给任务）：真实文献 + 收藏

- OpenAlex 检索、结果规范化、真实链接、DOI/OpenAlexID 去重、项目文献收藏；错误/配额管理。

### 阶段 4（后续单独给任务）：星图 + 研究设计 + 导出

- 基于真实引用数据的一层星图；两种研究设计路径；文献证据关联；方案编辑、保存、Markdown 实际导出。热点雷达属于次优先功能，只有在核心闭环稳定后完成，必须标来源日期。
- 验收：完整走通“模糊想法 → 研究种子 → 文献 → 研究设计 → 导出”的端到端真实流程，遇到缺失/失败时明确提示且不伪造结果。

### 阶段 5（后续单独给任务）：测试、优化与部署

- 清晰的上线检查清单、限流、权限测试、2 个陌生主题端到端测试、桌面和移动端验收、部署指导、课堂演示流程与录屏备用方案。
