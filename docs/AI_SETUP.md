# Paperi AI 接口配置说明

这一步用于连接真实 AI。你已确认的 UI 继续沿用；即使不配置，也能管理本地项目、手动编辑和保存研究种子。

## 你需要准备什么

需要一个提供 **OpenAI 兼容 Chat Completions 接口及 JSON object 输出模式**的 AI API 服务。

- ChatGPT Plus 是聊天产品订阅，不等同于 API 额度或 API 密钥。
- API 服务商可能要求单独开通或充值。是否开通、充值由你决定，Paperi 不会替你购买或充值。
- 模型由你配置；程序只在手动发送时调用该服务，不自动充值或选择付费资源。

可以先告诉 Codex 服务商名称，不要把密钥粘贴在聊天、截图或 GitHub 上。Codex 可以帮你核对公开的接口地址、模型标识和网络访问要求。

## 在 Codex 网页里配置

1. 打开当前项目的「编辑环境」，找到环境变量与密钥设置。
2. 在密钥设置中添加 `AI_API_KEY`，值填写服务商控制台生成的 API key。
3. 在环境变量中添加下表的 `AI_BASE_URL` 与 `AI_MODEL`。
4. 保存配置后告诉 Codex「已配置」。让 Codex 检查配置是否生效、域名是否允许访问，并重新启动网页服务。

| 名称 | 填什么 | 是否秘密 |
|---|---|---|
| `AI_API_KEY` | 服务商生成的 API 密钥 | 是，仅供服务器使用 |
| `AI_BASE_URL` | 服务商给出的 API 根地址，通常以 `/v1` 结尾 | 否 |
| `AI_MODEL` | 该服务商控制台中可用的准确模型标识 | 否 |

`AI_BASE_URL` 示例：OpenAI 官方接口根地址为 `https://api.openai.com/v1`。使用其他兼容服务时，应填写该服务商提供的地址。不要在根地址后填写 `/chat/completions`，程序会自动补上；不要将密钥写在网址里。模型需要支持 JSON object 模式与 `max_tokens` 参数；不同服务商、模型的兼容性仍需真实调用验证。

外部服务域名需要在云环境网络设置中允许访问。当前用户已选择 DeepSeek，`api.deepseek.com` 已实际连通。

## 如果在自己电脑运行

在 VS Code 中把 `.env.example` 复制为 `.env.local`，双击打开后填写上述三个配置，保存并重新运行「Paperi：启动网页」任务。这个文件已被 Git 忽略，不能上传。

无需配置 OpenAlex 或 Supabase 来体验本轮的本地研究种子功能。数据库尚未连接，当前保存范围仍是同一浏览器、同一网址。

## V1.1 阶段 A 怎样验收

1. 创建项目，进入灵感实验室，确认状态从「AI 待连接」变为「AI 已配置」。这只代表配置完整，不代表供应商已验证可用。
2. 从首页填写观察，点「开始探索」，自动进入同一段对话；首轮侧重理解现象，可继续选择概念，不再要求每轮返回 2–3 个问题。
3. 在概念、文献探索后选择真实收藏依据，再进入候选问题环节；采纳需主动编辑确认，也可手动记录研究种子。
4. 继续对话，确认已采纳的问题不会被自动覆盖；刷新页面检查对话与种子仍在。
5. 换一个不同主题的新项目，再完成一次，检查项目内容彼此隔离。完整本机步骤见 [阶段 A 验收](V11_STAGE_A.md)。

真实调用可能消耗你所选服务商的额度。页面不会自动发送，也不会在失败时自动重复扣费调用；「重试 AI 回复」需要你手动点击。切换页面时会取消浏览器等待，但已经到达服务商的请求仍可能计费。

## 目前的调用保护与边界

- 每条用户消息最多 2000 字；单次发送最近最多 20 条历史，总历史文本不超过 16000 字；更早的记录仍在本地保存，但不送入本次模型上下文。
- 单次输出上限 1800 token；等待最多约 30 秒；不自动重试。
- 单个服务器进程最多同时处理 2 次调用，最多 6 次/分钟、30 次/小时、100 次/天；失败尝试也计入限制。
- 限额是按运行进程维护的，重启后会重新计数。它不是账户级预算，也不是服务商消费上限；正式公开或多实例部署前仍需身份验证、共享限流和服务商消费上限。
- 无配置、密钥拒绝、额度不足、格式异常、超时均会明确提示。未完成的回答不会冒充成功结果。
- 对话和种子只保存在当前浏览器；清理浏览器数据、更换设备或更换网址后可能无法找回。
- AI 内容始终标为「建议 / 待核实」。用户采纳代表确认研究起点，不代表概念、理论或文献已得到学术验证。
