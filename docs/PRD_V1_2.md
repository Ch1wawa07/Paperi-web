# Paperi V1.2｜研究流程重构、文献星图与研究设计集中开发需求

## 一、项目背景与本轮目标

Paperi 是面向广告、新闻传播、社会学等人文社科研究初学者的 AI 学术研究导航网页。

目前 V1.1 已实现首页探索入口、AI 灵感对话、概念锚定、真实文献检索、项目保存等基础功能。但经过真实使用，发现现有产品存在严重的交互冗余、信息割裂、数据衔接不畅、检索结果相关性不足等问题。

**本轮目标不是继续细分研究流程，而是减少用户完成研究所需要的操作。**

产品应从“需要用户手动完成各步骤的研究流程工具”，升级为：

**AI 主动辅助理解问题、自动衔接概念与文献、可视化探索研究脉络，并帮助用户完成有依据的初步研究设计。**

### 本轮必须同时完成

1. 修复灵感实验室、文献探索等页面的布局和交互。
2. 重构概念选择、研究种子、文献检索之间的数据流。
3. 优化文献检索相关性与中文检索策略。
4. 实现真实的交互式文献星图。
5. 实现可编辑、AI 辅助的研究设计画布。
6. 完成必要的功能联调、旧数据兼容、整体 UI 精修。

**不要再把修复和新功能拆成多轮、每次只交付一个局部页面。**

可以在开发内部按依赖顺序逐步实现，但本次应集中交付一个可供用户完整体验的 V1.2 版本。

---

## 二、全局产品与工程原则

1. 基于目前 Paperi V1.1 已有工程继续开发，不得重建项目、随意替换技术栈或清空现有数据。
2. 保留 Paperi 的 Soft Glass 柔性玻璃视觉语言、品牌标识和整体审美风格。
3. 用户无需具备学术知识就能使用。专业概念和研究问题应由 AI 辅助探索，不应成为使用前必须填写的表单。
4. AI、项目、文献和研究设计必须共享同一份项目状态，避免用户跨页面重复操作。
5. AI 可以生成建议，但不得自动覆盖用户已确认的内容。
6. 学术判断必须区分真实来源、AI 解释、用户确认和待核实内容。
7. 不得伪造论文、DOI、引用关系、研究结论、研究空白或已验证量表。
8. 继续沿用现有 DeepSeek API 和学术接口，未经用户同意不得购买或启用额外付费服务。
9. 保留原有项目、聊天记录、概念、研究种子、文献收藏、分类和笔记。涉及数据结构修改时，必须实现兼容迁移。
10. 优先解决完整使用体验，而不是增加大量静态卡片、提示文字和装饰性步骤。

## 三、需求 A：全站页面布局与交互重构

### A1. 各功能页面首屏布局

当前灵感实验室、文献探索等页面存在大量纵向空间浪费。

以灵感实验室为例：页面顶部依次出现大标题、项目介绍、当前项目卡、阶段导航、说明区等，导致真正需要操作的聊天框和概念区被挤到页面下方。

**修改目标：进入页面，核心功能立即可见。**

要求：

- 压缩或合并各页面重复的大标题、返回入口、项目状态卡和说明区。
- 将当前项目、页面标题和必要操作整合成一条紧凑的工具栏。
- 研究进度提示可以保留，但必须轻量化。
- 灵感实验室的 AI 对话区、文献探索的搜索框、星图画布和研究设计编辑区必须成为首屏主体。
- 在 1440×900、1366×768 等常见桌面视口中，无需滚动即可看到核心输入控件。
- 主要内容区尽量占用实际可用高度，避免对话结束后出现大面积空白。
- 保持响应式设计，移动端可以折叠侧栏。

该规则应应用于所有主要功能模块，不要只修改灵感实验室。

### A2. 灵感实验室布局

目前左侧聊天框与右侧概念卡片的长度严重不匹配。概念区一列向下延伸，聊天区结束后左侧形成大片空白。

请重新组织内容布局。

建议：

- AI 对话区作为主要交互工作区。
- 候选概念改为更紧凑的响应式卡片网格，而不是始终沿右侧单列无限向下堆积。
- 在空间充足时优先使用双列卡片；窄屏时改为单列。
- 对话区与概念区可以采用独立滚动，避免其中一边内容过长导致整体版面失衡。
- 概念卡的主要文字应达到舒适阅读尺寸，正文建议不小于 15–16px，辅助文字不小于 13–14px。
- 概念解释默认精简，更多说明、概念边界和待核实事项可以展开查看。

**删除或大幅简化右侧重复的“现象理解”说明卡。**

现象理解应该主要由 AI 聊天回应完成，不需要在旁边重复出现大段相似内容。

右侧或顶部辅助区应重点呈现用户已选择的学术概念、研究进展和可执行的下一步操作。

## 四、需求 B：重构概念选择和研究种子逻辑

这是本轮最高优先级的产品问题之一。

### B1. 概念选择必须有明确反馈

当前点击“选择概念”后，只是按钮变成“取消选择”，用户很难直观看出自己已经选中了哪些概念。

改为：

- 概念卡有明确的选中视觉状态，例如边框、勾选标记和背景变化。
- 页面顶部或概念区上方显示固定的“已选概念”汇总条。
- 汇总条以概念标签显示所有已选择项。
- 支持直接移除、编辑和重新选择。
- 概念选择状态在刷新、页面切换和重新进入项目后保持一致。

### B2. 已选概念自动形成研究探索档案

用户选择概念后，应自动保存到当前项目的“研究探索档案”（可沿用研究种子结构）。

但是必须区分：

**概念已选定 ≠ 正式研究问题已确定。**

即使还没有明确的研究问题，系统也必须允许用户继续探索和检索文献。

建议研究种子采用两个状态：

**探索中：** 原始观察、已选择概念、关键词及可能的研究视角。研究问题可以为空。

**已确认：** 用户认可的研究问题、核心概念、研究范围以及后续引用依据。

### B3. 取消强制手动填写

目前“研究种子”需要用户填写研究视角、研究问题等内容，才能保存。用户根本不知道如何表达这些专业字段。

本轮要求：

- 用户选择概念后，系统自动生成研究探索档案。
- 用户可以直接点击“用这些概念探索文献”。
- 如果确实需要形成初步研究问题，可以由 AI 根据对话和选中概念生成可编辑草案。
- 不得强制用户先写出正式研究问题才能检索文献。
- 原有“研究种子”表单保留为高级编辑入口，而不是必须经过的步骤。
- 不允许产生没有实际意义的重复保存操作。

### B4. 跨项目数据隔离

目前出现了新项目填写研究种子时，显示上一个研究方向的快捷词、候选内容和旧检索词的问题。

请检查当前组件状态、项目 ID、路由查询参数、搜索初始化和本地持久化逻辑。

严格要求：

- 不同项目的概念、检索词、聊天、研究种子和研究设计互相独立。
- 从项目 A 切到项目 B 时，不能显示 A 的草稿、搜索词或候选概念。
- 新项目没有已选概念时，不应自动填入其他项目的内容。
- 返回旧项目时，旧项目自身的内容仍应恢复。
- 不能通过简单清空全部浏览器数据解决。

### B5. 概念与文献探索无缝衔接

新增明确操作：

**“根据已选概念查找文献”。**

点击后应：

1. 读取当前项目真正选中的概念。
2. 结合本项目原始观察及对话上下文。
3. 生成适合数据库检索的中英文关键词组合。
4. 自动带入当前项目的文献探索界面。
5. 允许用户修改关键词，或直接开始检索。

不能依赖已经过时的研究种子词组，也不能要求重新手动输入。

如果概念发生变化，相关检索建议应被标记为需要更新。

## 五、需求 C：文献探索体验与检索质量

### C1. 文献搜索框移至页面首屏

文献探索页面的搜索框应是最主要的视觉与交互入口。

要求：

- 搜索栏放在页面顶部主要工作区。
- 当前项目、已选概念及 AI 建议的检索词紧贴搜索区域。
- 高级筛选默认可收起。
- 搜索结果使用适合快速阅读的紧凑卡片形式。
- 不要把搜索框压在一大片标题、介绍和提示文字之后。

### C2. 修复跨项目与过时检索词

搜索输入应明确区分：

- 当前用户手动输入；
- 当前项目概念生成的推荐词；
- 当前项目已保存的历史搜索；
- 从其他页面主动带入的临时检索请求。

跨项目切换不得串用检索词。

如果用户当前手动编辑了关键词，后台异步生成的新建议不能自动覆盖用户输入。

### C3. 优化中英文检索策略

当前用户输入一组中英文混合关键词时，系统可能返回少量明显不相关论文。

请改造为：

- AI 识别研究主题与关键概念。
- 生成多组较短的中英文学术检索表达。
- 不要直接把全部中英文关键词拼接成一条超长搜索字符串。
- 可以分别执行检索并合并结果。
- 对 DOI、OpenAlex ID 等做去重。
- 对标题、摘要和研究问题进行相关性复核。
- 优先展示与当前研究直接相关的论文，次级展示方法学或理论背景文献。
- 无明显相关论文时应明确提示，而不是返回高引用但完全不相关的内容冒充成果。

保持透明：用户应该能看到实际使用了哪些检索词、哪些数据源，以及为什么推荐某篇论文。

### C4. 中文文献覆盖不足的处理

现有 OpenAlex / Crossref 中文学术覆盖有限，不能通过加强 AI 提示词宣称已经解决所有中文检索问题。

本轮先实现：

- 中文输入自动生成合适的英文检索表达。
- 中文、英文检索模式均可独立使用。
- 检索结果显示数据源及覆盖局限。
- 如果无法获得足够中文文献，不要伪造中文论文。
- 可支持用户手动导入 BibTeX / RIS / DOI 等真实参考文献元数据，优先选择维护成本较低的方案；如复杂则将其列入明确的待开发范围。
- 不得开发绕过权限的知网、万方爬虫。

### C5. 数据源切换自动适配筛选条件

当前从 OpenAlex 切换到 Crossref 时，如果“仅 CWTS 核心来源”仍然勾选，就会直接报错。

要求：

- 选择 Crossref 后自动取消不兼容的 CWTS 来源筛选。
- 对不可用的筛选选项禁用或隐藏。
- 用轻量提示说明“Crossref 不支持该来源筛选，已为你关闭”。
- 切回 OpenAlex 时允许重新开启，不得强制恢复原条件。
- 不得因不兼容筛选直接中断普通用户检索。

### C6. 相关性判断优先于形式上的权威性

文献卡增加：

- 与当前研究问题的相关程度；
- 推荐理由；
- 适合用作理论背景、概念定义、研究方法或直接相关研究的分类；
- 真实数据源、DOI、年份和可用摘要；
- 相关性判断依据及信息不足提示。

不要把被引次数、知名期刊或 DOI 存在与否直接换算成论文质量评分。

没有足够信息时，应标记“无法充分评估”。

## 六、需求 D：重新安排研究脉络分析的位置

当前研究脉络分析被安排在灵感实验室内部，但用户通常需要先完成文献检索和筛选，再返回实验室选择论文，才能分析研究脉络。

这种流程导致用户反复跳转、走回头路。

**研究脉络分析应主要归属于文献探索与文献星图，而不是灵感实验室。**

### 修改要求

1. 灵感实验室负责现象理解、概念探索和研究切入点讨论。
2. 文献探索负责检索、相关性判断、收藏和初步文献理解。
3. 文献星图负责论文引用关系、研究脉络、理论交叉与进一步探索。
4. 研究设计负责形成研究问题、理论框架及方法。

用户在文献探索中选择相关论文后，可以直接点击：

**“分析这些文献的研究脉络”。**

系统应自动使用当前项目已选择的文献和概念，不要求用户返回灵感实验室重新勾选一遍。

AI 生成的脉络分析应保留对应文献依据和信息不足提示。

## 七、需求 E：正式开发文献星图

本轮必须实现可操作的文献星图，不接受只有静态节点、漂亮背景或“待开发”字样的占位页面。

### E1. 核心交互

- 选择一篇已有真实文献作为中心节点。
- 读取 OpenAlex 等可获得的真实引用关系。
- 展示其参考文献和引用它的论文。
- 支持拖拽、缩放、点击节点、切换中心论文。
- 点击节点打开文献信息详情。
- 支持将节点对应的论文保存到当前研究。
- 初版控制节点数量与一层关系展开，避免无限请求和页面卡顿。

### E2. 研究脉络功能

除了引用关系，增加可切换的“研究脉络视图”，基于当前已确认文献尝试梳理：

- 已有研究的主要主题；
- 不同理论视角；
- 研究方法分布；
- 候选研究交叉点；
- 有依据的研究结论分歧；
- 尚需进一步查证的研究不足。

引用关系网络中的连线必须来自真实数据。

AI 归纳的主题关联应使用不同视觉样式，且不得将推测关系伪装成真实引用。

没有足够文献支持时，应诚实提示。

### E3. 与研究设计关联

用户从星图发现有价值的理论、文献或研究切口时，可以点击“加入研究设计”。

加入后自动保留来源信息，不需要在研究设计页面重新输入。

## 八、需求 F：正式开发 AI 研究设计画布

这是本轮最重要的新功能。

Paperi 的差异化价值不应停留在关键词和文献搜索，而应帮助研究初学者把前期积累的概念与文献转化为一个有依据、可修改、可继续实施的研究方案。

### F1. 研究设计入口

用户可以从：

- 已选概念；
- 初步研究问题；
- 文献探索；
- 文献星图；
- 现有研究项目；

直接进入研究设计画布。

不要求前面所有步骤都已经完成。

如果研究问题尚未明确，AI 可以根据项目已有材料提供候选问题供用户确认，并说明证据是否充分。

### F2. 两条研究路径

**定量研究：**

研究问题 → 理论候选 → 构念与变量 → 假设关系 → 研究方法 → 样本与测量建议 → 可行性检查。

**质化研究：**

研究问题 → 研究对象与情境 → 核心探索主题 → 理论或分析视角 → 访谈、观察或文本分析方案 → 样本与资料获取 → 可行性检查。

用户可以选择路径、返回修改或重新评估方法。

不能将所有研究都强制套入自变量—中介变量—因变量模型。

### F3. 可视化研究画布

希望研究设计不只是 AI 输出的一篇长文字。

请实现真正可交互的结构化画布：

- 可视化呈现研究问题、理论、构念/变量或质化主题；
- 关系可用节点及连线表达；
- 节点可以点击编辑、增删和调整；
- 定量研究可展示假设路径；
- 质化研究展示研究主题及资料收集路径；
- 点击理论、构念或方法时，可以查看其来源或待验证状态；
- 支持保存与重新打开。

视觉上延续 Paperi 的柔性玻璃语言，设计出有辨识度的研究工作台，不应只是一个普通文本表单。

### F4. AI 辅助生成与人工确认

AI 根据本项目的真实上下文给出候选内容，例如：

- 研究问题的不同切入角度；
- 理论适用性；
- 变量或构念建议；
- 候选研究假设；
- 质化探索主题；
- 研究方法与样本获取建议；
- 实施难点和潜在研究价值。

AI 建议必须可编辑、可接受、可拒绝。

没有充分文献支持时，不得自动宣称某个量表已经验证或研究空白已经成立。

### F5. 研究成果

本轮至少实现：

- 保存完整研究设计；
- 重新打开和编辑；
- 显示关联的真实文献；
- 汇总已确认内容、AI 建议与待核实事项；
- 导出一份可继续修改的 Markdown 初步研究设计方案。

如果 PDF 导出无法在保证质量的情况下稳定实现，可以后置，不影响核心研究画布交付。

## 九、交互与设计原则

### 1. 减少重复操作

如果用户已经选择了概念，后续检索和研究设计应自动读取这些概念。

如果已经收藏并选定了文献，不应该再要求返回上一个页面重复勾选。

如果研究问题尚未成形，不应该强迫用户凭空填写。

### 2. 提高页面可读性

避免过小文字、过密卡片、信息重复和大量无意义空白。

信息层级应当清晰：

核心操作优先，辅助信息其次，详细解释可展开。

### 3. 减少无价值的步骤

不以用户完成多少个阶段、填写多少张表单作为产品完成度。

真正的指标是用户能否更轻松地形成有依据的研究思路。

### 4. 保持视觉品质

保留目前令人满意的 Paperi 风格，但允许重新调整版面、信息层级、卡片比例、动效和组件结构。

优先完成真实交互，再进行全站视觉一致性精修。

## 十、本轮验收标准

请至少使用下面三个真实研究情境进行端到端测试。

### 测试案例 A：GEO 与广告传播

用户输入：

> 我想研究品牌通过 GEO 影响 AI 推荐以后，消费者为什么会相信这些推荐，以及他们是否意识到其中存在商业影响。

必须能够：

1. 识别并选择候选概念。
2. 自动形成当前项目的探索档案。
3. 一键进入真实文献检索。
4. 通过相关性筛选识别明显不相关的论文。
5. 保存文献并进入星图。
6. 从文献脉络进入研究设计。
7. 形成至少一个可编辑的初步研究设计方案。

### 测试案例 B：反向营销与心理逆反

用户输入：

> 我发现有些品牌故意劝别人不要购买，反而可能刺激消费者更想买。我想研究这种现象。

必须验证：

- 概念选择结果可以自动用于文献检索；
- 不需要填写正式研究问题才能开始探索；
- 搜索结果相关性能够被解释；
- 不应把机械工程、医学遗传学等明显无关研究标注为高相关；
- 可以从研究脉络形成定量或质化的初步方案。

### 测试案例 C：跨项目隔离

创建项目 A：AI 推荐与消费者信任。

创建项目 B：反向营销与心理逆反。

分别选择概念、检索和收藏不同文献。

验证：

- 项目 B 不出现项目 A 的快捷词、研究种子、检索历史或 AI 建议。
- 返回项目 A 后，原有数据完整恢复。
- 刷新网页后仍然正确。
- 旧版 V1.1 数据不丢失。

### UI 验收

- 灵感实验室首屏显示主要聊天工作区和概念操作区域。
- 文献探索首屏显示主要搜索框。
- 概念卡不再无限单列堆积，选中状态清晰。
- 对话结束后不会形成明显失衡的大面积空白。
- 文献星图可拖动、缩放、点击真实论文。
- 研究设计画布可以编辑和保存，不是静态示意图。
- 桌面和移动端布局无严重遮挡或横向溢出。

### 工程验收

- TypeScript、Lint、构建和相关自动化测试通过。
- 真实 DeepSeek 与文献接口测试通过，失败时显示真实错误。
- 没有新增未经授权的付费接口。
- 不暴露 API 密钥。
- 不破坏已有本地数据。
- 没有假按钮、硬编码论文、虚构引用关系或虚构研究结果。

## 十一、交付方式及执行要求

这是一次集中开发任务，不再要求每完成一个小阶段就暂停等待用户逐项验收。

请先检查现有代码、依赖和数据结构，制定内部实施顺序，然后连续完成上述改造与新功能。

内部优先级：

1. 修复概念、研究种子、项目、文献之间的数据流。
2. 统一各页面交互布局和导航逻辑。
3. 修复明显不相关的文献检索问题。
4. 完成文献星图和研究脉络视图。
5. 完成 AI 研究设计画布与基础成果导出。
6. 联调、测试、修复明显问题并统一视觉细节。

内部可以分批提交代码，但不要将一个未完成的占位版本包装成最终交付。

最终请提供：

- 本次修改和开发的功能清单；
- 实际完成与尚未实现的功能，分别说明；
- 三个真实案例的测试结果；
- 相关性评估和来源依据；
- 更新后的可运行代码及 GitHub 提交；
- 给零基础 Mac 用户的最简更新与启动方法；
- V1.2 的真实页面截图及必要的交互测试记录。

**重要：项目已经有一个用户正在本地使用的 V1.1 版本。请保留完整历史、兼容数据，并提供安全的升级方式。不要要求用户通过清空浏览器、删除旧项目或重新填写全部数据来完成升级。**

如果发现无法在当前免费接口、已有依赖和现有工程条件下完成某项功能，应给出具体技术原因及最小可用替代，而不是直接跳过或伪造功能。

请以 Paperi 真正解决研究初学者的实际问题为评价标准，而不是以页面数量、代码量和自动化测试数量为目标。
