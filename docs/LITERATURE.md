# 文献检索与分类收藏

阶段 3 已接入真实 OpenAlex 与 Crossref。保留已确认的磨砂 UI，没有预置论文，也没有让 AI 编造参考文献。实际运行证据见 [阶段 3 验收](STAGE3_ACCEPTANCE.md)，图片见 [截图图库](PREVIEW.md)。

## 怎样使用

1. 从右上角选择研究项目，打开「文献探索」。没有项目时也能搜索，收藏前需创建项目。
2. 可以直接填关键词或完整 DOI。已有确认的研究种子时，可点「生成中英文检索词」；这只调用 AI 建议关键词，不会自动搜索或替换输入。点击建议词加入，或选用英文组合，再自行精简。
3. 点击「检索」。默认相关性优先，限定期刊文章、有 DOI、OpenAlex 标记的 CWTS 核心来源。可改年份和排序，再点击检索生效。
4. 查看题名、作者、期刊、年份、来源记录和数据源摘要。「题名 / 摘要含」只列实际出现的词，不是 AI 打出的相关性分数。
5. 点 DOI 可到解析器，点「核查 DOI 登记」会重新向 Crossref 查询，并检查 DOI 解析器响应。题名或年份不同会提示人工核对；不会覆盖收藏信息。
6. 点「收藏文献」，选择一个或多个分类，写自己的阅读笔记，确认收藏。相同 DOI 跨来源也不会重复收藏。
7. 在「我的文献库」按分类查看、搜索题名/作者/期刊/笔记，或按收藏时间、更新时间、发表年、题名排序。分类可自建和改名；删除分类保留文献与笔记，失去所有分类的文献进入「未分类」。移出文献需确认，只影响当前研究。

每个研究有独立分类、收藏和笔记，同一篇论文可在不同研究里分别整理。默认分类为「待读」「核心文献」「理论与概念」「研究方法」；其中「核心文献」只是你自己的整理分类，不是系统认证。

## 真实、相关与来源质量分别怎样处理

- **真实来源：** 论文仅由官方固定接口返回；至少有有效 OpenAlexID 或 DOI，默认进一步要求 DOI。提供采集时间、原始登记链接及出版页面。空结果、超时、拒绝访问、额度不足和格式异常都有对应提示，不以示例或模型生成文献补齐。
- **相关性：** 保留用户检索词，默认使用 OpenAlex 的相关性排序；其排序也参考被引权重。可用更具体的英文概念、双引号短语和年份缩小范围。不会自动把陌生主题替换成预置主题，也不把搜索命中等同于适合引用。
- **来源筛选：** 默认同时限定 journal 来源、article/review、DOI 和 `primary_location.source.is_core:true`。CWTS 标记来自 OpenAlex 的来源元数据，是选择来源的公开依据；并不保证每篇论文经过何种评审或结论可靠。低被引的新论文不会仅因被引少而被本地规则排除。
- **备用来源：** 取消核心来源筛选后，自动模式可在 OpenAlex 故障时使用 Crossref，并明确显示来源切换。保持核心来源要求时，因 Crossref 不提供该标记而停止，不静默放宽要求。主动选择 Crossref 时也遵守这一规则。
- **精确 DOI：** 输入 DOI 时直接查 Crossref 登记，明确不应用关键词、来源及年份筛选。这用于查找已知文献，不冒充质量筛选后的推荐。
- **缺失与差异：** 未提供作者、年份、期刊、摘要等会明示缺失，不补造。OpenAlex 标为撤稿的记录排除；Crossref 检查其提供的撤稿关系，但来源状态可能不完整。在线发表与卷期年份可能不同，核查时显示差异，请以出版方对应版本为准。
- **全文：** 没有数据库全文权限，也不抓取付费正文。摘要只展示源字段；开放全文入口仅采用 OpenAlex 提供的 OA 位置。显示入口不代表已取得全文、全文链接永远有效或已读过全文。

中文期刊覆盖有限，尤其不能承诺覆盖知网、万方或 Web of Science。真实的 DOI 登记也可能对应质量较差的论文；最终引用仍应查看作者、出版方、研究方法及原文。本轮没有声称所有收录论文都「权威」。

## 配置与费用

本轮实际验证时，OpenAlex 未配置个人密钥仍能返回 200；响应注明匿名访问共享网络出口的免费日额度，额度和政策可能变化。Crossref 公共元数据接口也已实际验证。

需要独立额度时，由用户自行到 [OpenAlex API 设置](https://openalex.org/settings/api) 查看当前免费政策、注册并取得密钥；在云环境的环境变量/秘密设置中新建 `OPENALEX_API_KEY`，安全填写，再重启服务。不要贴到聊天、前端变量或 Git。仅密钥被服务端读取，不包含在浏览器响应中。没有代为注册、发邮件、购买或升级服务。

AI 检索词建议沿用现有 DeepSeek 配置和余额，点击才调用；手动搜索和收藏不需要 AI。跨站发送研究种子会被拒绝。

本环境 Node 24 启动需要 `NODE_USE_ENV_PROXY=1`，继承平台代理、CA 和 `NO_PROXY`。文献接口需允许 `api.openalex.org`、`api.crossref.org`、`doi.org`；不需要为了核查而放开所有出版方域名，服务端只检查解析器，不跟随其跳转抓取正文。

## 保存与请求边界

收藏仍保存在当前浏览器、当前网址的 localStorage。刷新和重开标签页可以恢复，换设备/浏览器/域名/端口不会自动同步；清除站点数据会丢失。Supabase 尚未配置，不宣称云同步。

每研究最多 300 篇、30 分类，笔记最多 4000 字。写入失败保留原状态和编辑内容；分类/笔记带修订号，其他标签修改时旧窗口不会静默覆盖。localStorage 不是数据库事务，真正多用户并发仍需后续数据库。

检索每页 10 条，最多浏览前 5 页，成功响应最多缓存 80 组、5 分钟。元数据请求超时 16 秒、响应上限 3 MB；单进程每分钟最多 30 次非缓存检索/核查，同时最多 3 次。DOI 解析检查最长 8 秒，不自动重试。额度保护随进程重启重计，不代表公共部署所需的用户级预算系统。AI 建议沿用既有 AI 限额，每次最多 700 输出 token。

开发维护入口：`src/lib/literature-server.ts`（固定上游、筛选、限流、缓存、核查）、`literature-mapping.ts`（来源字段规范化）、`literature.ts`（标识/保存校验）、`src/components/literature.tsx`（检索与整理）。`Project.library` 为可选字段，兼容之前的项目。
