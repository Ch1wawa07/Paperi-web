# Paperi V1.1 · 阶段 A 验收与本机预览

2026-10-21（北京时间）。本轮只改入口、导航和分阶段研究探索，保留 Soft Glass 材质与品牌。阶段 B 的相关性修复、阶段 C 的真实引用星图、阶段 D 的文献评估均未开始。完整新需求见 [V1.1 原文](PRD_V1_1.md)。

## 这次实际改变了什么

- 首页点「开始探索」后先保存原始观察，创建简短临时标题的项目，自动进入灵感实验室并发送第一条消息。首页和实验室只用这一份历史，不再要求复制、二次发送或先填写正式名称。
- 项目名称与观察分别存储；可在最近项目中改名。「仅新建项目」是明确的次级入口，不会自动调用 AI。
- 首页欢迎区与输入区缩小，五个主要入口在常见桌面首屏内可见，项目区改为紧凑列表。桌面为左侧固定导航，小屏折叠菜单；所有环节均可自由访问。
- 灵感探索有六个可往返状态：现象理解、概念锚定、文献初探、研究脉络、候选问题、设计衔接。切换只保存状态；点「探索这一环节」才发送对应请求。
- 早期不再强制生成 2–3 个问题。AI 可以先梳理现象与概念；概念支持选择、修改、排除、恢复和追问。用户改过或选过的内容不会被后续建议覆盖。
- 文献初探生成独立的中英文短组合，点击可带入现有文献搜索框，仍由你编辑、点击检索。每个环节最近一次建议会保留，往返不会为了恢复面板而重新付费生成。
- 研究脉络和候选问题环节可主动选择本项目收藏作为依据，最多 5 篇。候选问题生成前需有已选概念与至少一篇所选文献；模型引用的文献 ID 必须属于此次提供的依据。没有数据不会填充假依据。
- 研究种子仍由用户编辑确认；新增可选的文献关联，设计页面能读取同一项目的问题、概念与关联题录。它只是资料衔接，设计画布尚未实现。

概念是候选解释，不冒充操作化定义；只有题录/摘要时只作有限讨论，不声称读过全文，也不把有限检索解释成“无人研究”。收藏中的每篇论文是否真正适合引用，仍需人工核实。

## Mac 上实际体验

当前 Codex 环境设置会话没有用户可打开的私有网页预览入口。「保存并发布环境」不是发布 Paperi 网站。未搭建公开隧道或购买托管服务。

1. 如未安装，先安装免费的 [Node.js 24 LTS](https://nodejs.org/zh-cn/download) 与 [VS Code](https://code.visualstudio.com/)。
2. 在 GitHub 切到 `codex/paperi-stage1` 分支，点 Code → Download ZIP，解压后用 VS Code 打开包含 `package.json` 的文件夹。聊天交付也会给出固定验收版本 ZIP 链接。
3. 如果你已在 Mac 配过 Paperi，把旧目录的 `.env.local` 复制到新目录。首次运行则把 `.env.example` 复制为 `.env.local`，填写原来的 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`，按 ⌘S 保存。不要发到聊天或提交 Git；云端密钥不会随下载自动带到 Mac。
4. 停止旧的本机服务。在 VS Code 点「终端 → 新建终端」，依次执行：

   ```sh
   npm ci
   npm run build
   npm run start -- --hostname 127.0.0.1
   ```

5. 显示 Ready 后，在这台 Mac 的浏览器地址栏输入 `http://127.0.0.1:3000`。这是你本机启动后才能使用的地址，只监听本机。结束时在终端按 Control+C。

原来浏览器的项目属于原来的网址。请保持原浏览器、原地址和端口：`localhost:3000` 与 `127.0.0.1:3000` 是不同存储空间。如果以前用 `localhost:3000`，本次继续在浏览器输入 `http://localhost:3000`，不要清除站点数据。更换项目文件夹不会自动清空同一浏览器同一网址的数据。

本机运行不需要购买云服务。你点击开始探索、发送或探索当前环节，会使用已有 DeepSeek API 余额；切换环节与恢复历史本身不调用模型。OpenAlex 仍沿用现有可选个人密钥与匿名免费额度机制。

## 建议你亲自验收的顺序

1. 首页输入一段自己的生活观察，点「开始探索」。应直接看到原话和真实回复，没有创建名称窗口，也不用重复发送。
2. 查看现象理解，切到概念锚定；选择一个概念、修改解释、排除另一个，再追问。刷新后检查选择、修改、排除与聊天仍在。
3. 切到文献初探，点「探索这一环节」。选择一组英文词进入文献探索，确认搜索框已填入这一个组合，可以修改后检索。
4. 收藏论文，返回灵感探索，在研究脉络中选择此次讨论的文献依据。信息不足时应明确受限，不伪造全文分析。
5. 在候选问题中请求辅助收敛；也可手动记录问题。采纳需你确认。继续聊天不能覆盖已确认种子。
6. 创建另一项目再探索，确认对话、概念和收藏彼此独立。回到旧项目核对旧聊天、种子、分类和笔记。
7. 可用临时断网验证失败：原消息应保留，恢复后点「重试 AI 回复」。已发出的请求失败后，刷新不应自动重发或新增项目。

自动测试与维护者联调不代替你的体验验收。阶段 A 结束后暂停，等你确认才进入阶段 B。

## 实际验证记录

- TypeScript、Lint、生产构建通过；46 项自动测试全部通过，0 失败、0 跳过；详见 [测试记录](TEST_RESULTS.md)。
- **反向营销与心理逆反：** 在同一个首页创建的项目中完成首轮、概念锚定、主动选择概念、刷新恢复、文献初探与短组合跳转。关键词 `psychological reactance advertising persuasion` 经现有 OpenAlex 返回 10 条记录，真实收藏成功。此项只作为接口/衔接回归，不宣称检索质量改造已经完成。
- **AI 推荐与消费者信任：** 首页自动发送、现象理解、概念锚定、选择概念、刷新恢复均通过。早期回复没有研究问题卡。切回前一个项目，历史和选择各自保持。
- **旧数据：** 从阶段 3 实际联调的旧浏览器状态复制到隔离测试浏览器，读取两个旧项目，再保存新的探索状态；旧种子、全部聊天、候选方向、收藏、分类、笔记逐项比较均不变。这次检查没有新增 AI 请求。
- **界面：** 1440、1280、768、390px 六路由回归；1280×900 主入口在首屏；390px 概念编辑、辅助面板收起和页面无横向溢出。
- **真实服务问题处理：** 早期 DeepSeek 把已有的方向数组嵌入 guide，现只移动这个实际存在的数组到约定位置，再完整校验，不生成内容。文献初探也遇到空回复；拆为更短、每次最多 700 token 的专用请求后真实重试成功。空回复仍报错，保留原消息，不自动重试。

[结构化真实联调证据](v11-stage-a-evidence.json) 记录实际主题、返回内容、检索记录与恢复检查；其中 AI 概念解释都是待核实建议。测试夹具没有混入真实页面或检索结果。

仍使用 `paperi.projects.v1`。旧项目不要求新字段，旧消息、方向、种子和文献库无需删除或重建。`exploration.navigation`、`launch` 与 `seed.evidenceIds` 都是可选扩展；确认内容只有用户保存时才更新。历史方向可在「已保存 / 旧版候选方向」展开查看，保留编辑采纳和丢弃能力。

首次请求先保存原话，再保存已尝试标记，成功回复才追加历史。刷新不重复已尝试的首轮。支持 Web Locks 的浏览器还会协调首次发送；本地存储写入失败时停止自动尝试并保留手动重试。它仍不是多用户事务型数据库。

## 已知限制与下一步

- 明显偏题结果过滤、多个检索组合合并去重、广泛探索筛选与文献适配解释属于阶段 B / D，未在本轮实现。现有期刊/DOI/CWTS 默认筛选暂未改变。
- 真实引用星图留待阶段 C；设计画布和方案导出尚未开发。
- 仍是当前浏览器本地保存，尚无 Supabase 云同步。
- AI 可能返回空内容、格式不完整或事实错误；明确失败和重试保护不等于保证每次模型生成成功。普通对话仍最多 1800 输出 token，检索组合 700；沿用原分钟/小时/日限额，不自动重试或购买资源。
- 研究脉络/候选问题的文献 ID 检查、问题采纳和传递由隔离测试验证；两主题真实服务主要验收首页、现象/概念探索与文献衔接。不能据此宣称学术质量或完整研究设计已验收。
