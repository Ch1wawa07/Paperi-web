## 本轮实际修复

- 用明确题名字段、首页/封面的字号与位置、同字号换行标题、正文佐证的 PDF 属性识别候选。文件名只是显式标记来源的回退。无高置信候选显示“题名待核对”，不再拿任意首行补齐。
- 排除日期、摘要、章节、生产工具/占位属性及作者中的单位、地址、邮箱/职称。旧记录不自动改写；不可信的未确认 PDF 题名在卡片里显示待核对，原字段仍可在校对中查看。
- “已导入文献 → 批量校对书目”：每篇题名、作者、年份、出版来源分别编辑，一次保存当前项目。显示 PDF 正文/PDF 属性/文件名/用户确认来源；缺字段继续待核对。可手动从已有 PDF 重新取候选，不需要重传文件。
- 编辑保持 SavedPaper.id、attachment.id、PDF Blob/pages、笔记和旧分析。旧分析不删除；对应书目变化后标记待核验。新精析指纹只依赖该篇与研究上下文，其他篇改名、资料集合切换不会把它误判过期；旧指纹仍兼容读取。
- 本地诊断导出需展开、勾选并主动下载。只含所选文件名、四项书目候选/当前值、页数/各页字数、封面/摘要/方法/结果/结论最多5处短片段（每处450字）；最多20篇、64 KiB。过滤邮箱、地址/联系信息与凭证行。不导出 Blob、全文、研究观察或环境配置；不自动上传。**分享前仍需用户复核脱敏结果**。
- 精析逐节验证并保留有效部分，缺节用“暂无可靠依据”而不是编造内容。兼容少量明确标题别名，不任意猜板块。错误来源、字段/页码无效、原文引句不匹配分别标注。
- 输出截断/JSON损坏时仅恢复 `sections` 数组中已完整结束的 JSON 对象，再做正常证据核对；不为半截内容补括号或补结论。若无完整项，返回明确错误。余额、凭证、限流、超时继续明确反馈，没有自动重试。
- 本地终端 `[Paperi reading]` 诊断只记录错误代码、HTTP状态、token上限、结束状态、输出字符数、板块计数与问题代码。**不记录密钥、原始模型内容、PDF文本或个人联系信息**。
- 每一失败/不完整板块可“只重试本节”，合并时保留其他六节、保留旧版本。已返回但保存失败时仍可只保存，不再调用模型。整篇输出预算5200 tokens，单节2200；每次操作最多一次模型请求，未放宽生产限流。
- 节选优先摘要、假设、方法、结果、讨论、结论的页及其实际位置窗口；不只是每页开头。精析至多40000字符；UI展示具体覆盖页、局部页、整页遗漏、预算限制，接口失败时也能查看本次准备的覆盖情况。只有题录不调用AI，不假装读过全文。PDF未识别为可读文本时不提供OCR。
- 沿用七节与既有紧凑排版。总论要求口语化回答问题/方法/发现；原文事实各自带引句/页码。“关键发现与结论”独立列出逐项关系、原文结果、支持/未支持或无显著性/未检验/信息不足。数字须出现在相应引句中，明显与引句相反的支持标签不采用。AI选题建议仅在单独区域展示。**引句确实存在不等于AI解释已被证实**，需人工对照上下文和表格。
- 可直接打开当前浏览器原PDF的对应物理页（阅读器是否精确定位取决于浏览器支持 `#page=`，可按显示的页码手动定位）。不会访问另一项目的文件。
- “带着通过检查的文献去梳理研究脉络”只选书目人工校对/外部核验且核心三节无质量错误的当前精析。允许先3篇、再5篇；保留手动选资料入口。脉络按篇提供主题/方法/结果的引句，未获支持的关系不当作已支持，最后的切口始终是待检验提议。

## Mac 安全更新（GitHub ZIP）

1. 保留旧目录。先在原 Safari 导出项目 JSON，并分别保留/下载五篇 PDF 原文件；JSON并不包含 PDF Blob。不要清理站点数据或恢复覆盖当前项目。
2. GitHub 仓库 `Ch1wawa07/Paperi-web` 选择分支 `codex/paperi-stage1` → Code → Download ZIP，解压至新目录。将旧目录的 `.env.local` **仅在本机**复制到新目录；不要发送、截图或提交密钥。`AI_API_KEY` 原配置优先级和 `DEEPSEEK_API_KEY` 回退不变，云端不会替你写入密钥。
3. 在新目录执行 `npm ci`。停止旧服务，再 `npm run dev`。继续使用**同一个 Safari 浏览器配置、同一个 `http://localhost:3000`**，不要切换端口或清理 localStorage/IndexedDB。原项目和 PDF 应直接出现，无需重导入。

## 三步真实验收（尚待用户本机完成）

1. **五篇书目校对**：进入原项目的已导入文献，批量对照每份原PDF填写题名、作者、年份、期刊/机构。无依据字段留空；人工确认不是外部数据库认证。一次保存后刷新，检查五张卡片，再从编辑入口下载原PDF，确认仍是原文件。识别仍异常时手动导出所选文献诊断，分享前自行检查；云端需要该诊断才能继续定位实际版面问题。
2. **第一篇一键精析**：优先选择截图中曾成功的抖音短视频论文。点击前确认该操作可能消耗现有AI余额，只点一次。核对本次覆盖页，读总论与逐项结论，逐条打开原PDF检查原文是否支持/未支持；没有显著性不等于不存在效应。异常时按具体错误检查配置/余额/节选，并对失败节手动重试，不反复整篇调用。**这一步需真实PDF和本机密钥；本轮云端未验收其结论正确性。**
3. **至少三篇梳理研究脉络**：逐篇核对到至少三篇核心节通过基本检查后，点击“带着通过检查的文献去梳理研究脉络”，确认资料选择只有这三篇，再点击梳理（单次可能计费）。检查共同主题、方法差异、结论异同每项是否引用正确论文和页码，候选切口是否明确为待检验。之后核对剩余两篇再加入。任何具体中介或大学生问卷方案都不能冒充五篇共有结论。

若需云端完整核验五篇最终结论，仍须另外提供允许处理的PDF原件；短诊断只能帮助识别/截取/报错定位，不能代替完整原文验收。
