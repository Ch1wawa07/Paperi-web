# 导入入口、PDF 卡住修复与彩色磨砂界面

基于 `c3c8701` 接续修改，保留所有项目存储和研究工作流。

## 入口

空项目打开文献工作台直接进入导入页；第一个操作始终是“导入文献”。只有导入或原有文献存在时才显示“已导入文献”，不再让新用户先面对空收藏夹。已有项目仍可直接管理文献，导入按钮始终位于首位。

## PDF 卡住的原因与修复

用户确认卡在导入时的“读取文件”，并非 AI 精析。发现 `LibraryWorkspace` 原来的 mounted ref 只初始化一次为 true，effect cleanup 设置 false，effect setup 没有恢复。Next 开发模式的 React StrictMode 会执行 setup → cleanup → setup，因此 ref 保持 false。解析完成后代码因“已卸载”误判跳过预览及 pending 清理，造成永久显示读取中。此前测试只运行 production server，没覆盖这一实际开发模式。

本次修正 setup 中恢复 mounted，并在卸载时取消读取。新增独立 `playwright.dev.config.ts`，使用真正的 `next dev --webpack`、真实本地合成 PDF、实际 PDF.js 和 Chromium，验证出现预览、确认入库以及无浏览器异常。

此外增加：

- 打开文件、逐页提取和整理预览的明确状态；标明本地解析，不调用 AI。
- 主导入和文献编辑附加 PDF 都可取消。
- 单个异步阶段最多 15 秒，总解析最多 60 秒，超时释放 worker 并给出可恢复错误。
- 需要密码的 PDF 立即提示在本地解密，不停留在等待密码状态。
- `npm ci` 的 postinstall 同步 PDF.js worker、中文 CMap 和标准字体到本地 public 目录，运行时不依赖 CDN。
- 保留 20 MB / 150 页 / 60 万字符上限；扫描件没有 OCR，不能提取文字时仍诚实报错。

未取得用户当时卡住的原始 PDF，因此不能声称验证了该具体文件；本次确认并修复的是可由开发模式生命周期直接触发的真实缺陷，也处理了真正慢文件的有界退出。
