# Paperi：研究脉络、方向共创与初步研究设计

本次增量开发以 `bb147c9` 为基线，保留原项目存储、PDF、文献精析与旧版历史。阶段 A 数据安全 checkpoint 为 `c64fb03`，阶段 B 主流程 checkpoint 为 `5182952`，均已正常推送到 `codex/paperi-stage1`。

## 入口与工作流程

首页保留原始观察，四个专业入口为灵感实验室 `/lab`、概念锚定 `/concepts`、文献工作台 `/literature`、研究脉络 `/research`。概念选择仍使用项目内原有的一套状态；选择、排除和修改不复制到新档案。点击“根据已选概念准备检索”后，基于本次选择准备双语词；页面打开、刷新或输入字符不会自动付费请求。

研究脉络内部依次为“看懂已有研究”“继续研究什么”“我的研究方向”“我的研究设计”，可随时往返。文献精析末尾与已导入列表可进入研究脉络；默认带入当前项目全部文献，已有分组选择则沿用，不重复上传。无需先精析全部论文。

梳理只生成四类跨文献分析。方向推荐由用户单独点击触发，结合对话中的对象、方法偏好及排除项给出候选。AI 不替用户确认或覆盖方向；方向编辑和历史版本保留。设计必须先有用户确认的方向。

## AI 上下文和证据边界

新增 `/api/research-journey` 复用现有 `AI_API_KEY / AI_BASE_URL / AI_MODEL` 与 `DEEPSEEK_API_KEY` 配置和生产限流，不新增平台依赖。每次操作只请求一次模型，不自动重试。按任务使用 2200–3600 token 输出预算；超时、无配置、余额、配额、格式和未知文献引用均有错误反馈。

上下文包含原始观察、有限灵感对话、已选与排除概念、选用题录/摘要、七维精析要点与引句页码、已有脉络、最近讨论、偏好、拒绝角度、候选、已确认方向和当前设计步骤。脉络阶段最多发送 36000 字的 PDF 节选；后续讨论不重复发送整份 PDF。上下文总长度有预检上限。过期分析、缺失 PDF 与仅题录均明确区分。

可核对引句必须来自本次摘要或有页码节选；无法匹配时，事实性归纳降为资料不足。引句匹配不能证明 AI 解释完全正确，仍须人工核查。研究方向、变量和方法均为待验证建议；不会把 AI 建议当成论文结果或假定完整阅读全文。讨论可展开查看其使用资料与边界。AI 等待期间修改资料，返回内容仍绑定发起时的来源版本。

## 两种设计

定量按研究问题、变量、假设与模型、实施建议分步。变量角色、解释、依据和待核查事项可编辑；假设绑定真实变量 ID。图在站内以 SVG 确定性绘制，候选与确认状态区分，节点/连线可点开编辑；改名和删除即时联动。方法建议说明横截面问卷的局限，不把关联当因果。

质性独立保存研究问题、对象/情境、主题、开放式提纲、招募、记录/编码/主题分析与伦理建议，不强制变量或 H1–H3。主题变化会提示核对提纲。切换方法先提醒，保留另一种草稿；生成与保存历史可恢复。方案可编辑、保存、复制普通中文、浏览器打印，内部 ID 和 JSON 不作为成果呈现。

## 数据保护

`paperi.projects.v1`、`paperi.files.v1` 保持不变。新增可选 `workflow.research`，旧项目可直接读取；旧综述/节点设计只读保留并进入完整备份。旧方向卡和脉络通过只读适配展示，不伪造迁移旧设计。

脉络、讨论、候选、确认方向、两种设计各自保存。删除或更新文献只标记资料待复核，保留旧方向、设计和历史引用，可由用户解除已移除文献的关联。变更依赖包含题录、PDF、概念和已保存精析，讨论或设计编辑不会使自身无故过期。异步保存按队列合并本次变更，避免失焦保存被阶段切换覆盖。设计的 AI 请求期间暂停编辑，防止返回结果覆盖等待中输入；取消入口保持可用。已有环节用“重新建议这一环节”明确区分再次付费请求。

正常保存进入项目备份；未完成的输入另有按项目/方法隔离的浏览器恢复副本，版本不符时不会静默覆盖较新的已保存设计。未完成的方向名称可以暂时留空并恢复；恢复逐字段核验，损坏的一项不会丢弃其他有效输入，正式项目和确认方向仍保留严格校验。它是输入恢复辅助，正式备份前仍请点击保存。恢复备份创建独立项目，沿用已有 PDF 所有权保护，不会删除原项目文件。

## Mac ZIP 实际验收

1. 从 `codex/paperi-stage1` 下载最新 ZIP，解压到新目录；保留原目录作回退，把原 `.env.local` 仅复制到新目录本地，不上传密钥。运行 `npm ci`，停止旧服务，运行 `npm run dev`。
2. 使用原来的浏览器与 `http://localhost:3000`，不要清除站点数据或切换隐私窗口。项目和 PDF 在浏览器，不在 ZIP；更新前先通过站内备份保存项目，并单独保存 PDF。
3. 使用三篇真实中文文字 PDF，完成导入与七维精析，核查实际页码引句。进入研究脉络梳理；输入“主要研究大学生，偏问卷，不做复杂实验”，保存偏好，再明确点击推荐方向。检查是否参考上下文及局限，而不是把示例当结论。
4. 修改并确认一个方向，逐步生成定量变量与假设。改名变量、删除 H2，核查站内模型同步；保存刷新并复制/打印。切换质性，确认原定量草稿保留，再生成和编辑主题/提纲。
5. 删除一篇引用文献、切换两个项目、刷新及停服重启，核查待复核提示与各自成果、PDF 保留。错误时不得覆盖既有内容，也不应自动连续请求。

没有服务端密钥时，设置仅限本地 `.env.local`，例如 `AI_API_KEY=<自己的测试密钥>`、`AI_BASE_URL=<服务商的兼容根地址>`、`AI_MODEL=<实际可用模型>`；或沿用现有 `DEEPSEEK_API_KEY`。不要把真实密钥粘贴到聊天、提交到 Git 或使用 `NEXT_PUBLIC_`。修改后重启服务。
