# Paperi 纸里

**让好奇长成研究。** 面向广告、新闻传播、社会学等人文社科研究初学者的 AI 研究导航网页。

当前完成 **V1 阶段 1：网页基础工程和本地项目管理**。没有公开部署，没有购买服务。后续产品需求见 [完整 PRD](docs/PRD.md)，进度见 [实施计划](docs/IMPLEMENTATION_PLAN.md)。

## 现在能做什么

- 浏览首页、灵感实验室、文献探索、文献星图、研究设计画布、研究方案六个页面。
- 创建项目、填写名称及研究领域、保存起始观察、改名、切换项目、继续项目、确认后删除。
- 项目保存到**当前浏览器本地**；同一浏览器、同一网址下刷新或关闭标签页后重新打开仍可恢复。
- 手机上的折叠菜单、键盘操作、加载状态、空状态、错误及保存反馈。

AI 聊天、研究种子编辑、论文检索/收藏、关系图、设计编辑和导出**还没有接入**。对应页面均会说明后续阶段，没有假聊天、假论文或假统计。

## 没有编程基础，怎样查看

### 先看截图

在 GitHub 上可直接打开 [实际运行截图](docs/PREVIEW.md)，无需下载或安装软件。

### 在自己的电脑交互体验（无需输入代码）

当前没有已经上线的网址，云环境中的地址不能直接当作你电脑的网址。

1. 安装 **Node.js 24 LTS** 和 **Visual Studio Code**，使用各自官方网站的安装程序。安装后重启 VS Code。
2. 获取本次审核后的完整代码文件夹，用 VS Code 的「文件 → 打开文件夹」打开 `Paperi-web`（这一层有 `package.json`）。如果 GitHub 仍然只有 README，说明本次改动尚未合并回 GitHub；应先通过本任务的代码改动审核流程获取代码，不要反复下载旧版本。
3. 点 VS Code 菜单「终端 → 运行任务」，选择 **Paperi：首次安装依赖**。等待出现安装完成且没有错误。只需首次或依赖更新后执行。
4. 再点「终端 → 运行任务」，选择 **Paperi：启动网页**。保持该任务运行。
5. 在**这台电脑**的浏览器地址栏输入 `localhost:3000`。这只在你自己的电脑上提供预览，不会发布为公开网站。
6. 查看后，在 VS Code 的「终端 → 终止任务」中停止 Paperi 启动任务。

若云环境未来提供经过确认的私有端口预览功能，可以通过该功能查看运行中的 3000 端口；本次没有可用的外部预览链接，也未配置公开转发。不要把云端的 `127.0.0.1` 当作可分享地址。

## 建议的验收步骤

1. 在首页写一段观察，点「保存想法，开始探索」，确认名称并创建项目。
2. 点「继续项目」，在灵感实验室看见刚才的原始观察；页面同时明确 AI 待连接。
3. 刷新网页，回首页，项目应仍在。创建第二个项目，从右上角切换，再跨页面查看当前项目。
4. 尝试重命名、取消删除、确认删除；确认只删除所选项目。
5. 缩窄浏览器或用手机打开同一可用地址，展开导航，逐一查看六个页面并返回。

**本地保存的限制：** 不等于云同步；更换设备、浏览器、网站地址或端口，使用隐私模式、清理浏览器数据都会使原项目不可见或丢失。不要在阶段 1 保存无法替代的私密研究资料。删除不可撤销。

## 环境配置

**阶段 1 不需要注册 AI、OpenAlex 或 Supabase，不需要填任何密钥。** 所有界面和项目操作在未配置状态下可用。

`.env.example` 只是未来配置项的空占位说明。后续接入时，由开发者在环境设置中安全填写，或复制为被 Git 忽略的 `.env.local`：

| 变量 | 后续用途 | 何时需要 |
|---|---|---|
| `AI_API_KEY` | 服务器调用真实 AI，不能公开到浏览器 | 阶段 2 |
| `OPENALEX_API_KEY` | 真实文献接口认证与配额 | 阶段 3 |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 项目地址 | 阶段 2 条件具备时 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 受 RLS 保护的公开客户端标识 | 阶段 2 条件具备时 |

这些变量目前不参与应用逻辑。不要向聊天或 GitHub 上传真实密钥；绝不能把 Supabase service role key 放到前端。

## 给后续维护者的运行与检查说明

技术：Next.js App Router、React、TypeScript strict、Tailwind CSS 4 + 定制 CSS；精确依赖版本和完整性校验写入 `package-lock.json`。建议 Node.js 24 LTS，最低 22。

以下命令均在仓库根目录执行。初学者可直接使用上方菜单任务，无需自行输入命令。

```sh
npm ci
npm run dev
# 停止开发服务后，可以验证生产模式：
npm run typecheck
npm run lint
npm run build
npm run start
```

在当前 Codex 云环境，npm 的默认缓存目录不可写，安装时使用 `npm ci --cache /workspace/.npm-cache`。这只是机器缓存路径调整，没有绕过 TLS 或软件完整性校验。

浏览器验证（先成功 build，测试会自动启动并结束本地生产服务）：

```sh
npm run test:e2e
```

本云环境复用 `/usr/bin/chromium`。其他机器可执行 `npx playwright install chromium`；测试配置会自动采用系统 Chromium（若存在），否则使用 Playwright 安装的浏览器。也支持通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已安装的浏览器。不要在另一个版本的服务占用 3000 时运行测试；持续集成设置 `CI=1` 会拒绝复用既有服务。

测试覆盖范围和实际结果见 [阶段 1 测试记录](docs/TEST_RESULTS.md)。自动截图和 HTML 报告分别在 `test-results/` 与 `playwright-report/`，被 Git 忽略。404 页面也有返回首页入口。

## 数据与结构

- `src/lib/projects.ts`：Project 类型、带版本校验的存储结构、异步 `ProjectRepository` 接口与本地适配器。
- `src/components/project-provider.tsx`：共享当前项目状态、保存反馈、多标签页更新与失败保护。
- `src/components/home.tsx`、`project-dialog.tsx`：原创首页和真实项目操作。
- `src/components/shell.tsx`：六页通用导航、项目切换、移动端菜单。
- `src/components/module-page.tsx`：后续模块的真实未接入说明。
- `src/app/globals.css`：颜色、字体、圆角、阴影等视觉 Token 和响应式规则；无外部字体、图片或第三方跟踪请求。
- `docs/`：原始完整需求、阶段计划、技术取舍和验证记录。

存储键为 `paperi.projects.v1`，结构带版本、修订号和数据校验。先保存成功再更新界面。遇到读写受限、容量不足或格式异常会提示，不会悄悄重置为演示内容。修订号帮助识别过期页面，但 localStorage 不是多用户数据库，不能保证极端同时写入的事务一致性。后续 Supabase 迁移需要明确设计导入与冲突处理。
